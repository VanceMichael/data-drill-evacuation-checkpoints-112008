# 场馆消防演练签到采集与人员清点

这里是可离线启动的合成上游，所有编号、时间和凭据都用于联调。

## 本地运行

使用 Node.js 22.23.4。项目只使用随 Node.js 提供的运行库。

```sh
npm start
npm test
```

不同终端分别启动服务和执行独立来源测试。默认地址为 `http://127.0.0.1:4173`，可通过 `SOURCE_PORT` 设置端口，也接受通用的 `PORT`，同时设置时以 `SOURCE_PORT` 为准。`GET /health` 用于确认来源服务已就绪。来源使用进程内演练时钟，启动时处于 `gather`。用 `PUT /_source_clock?step=reroute` 推进到下一阶段，`GET /_source_calls` 查看本实例收到的业务请求。可查阶段为 `gather`、`reroute`、`seal`、`catchup`、`following`。重启服务会重置时钟和请求记录。预置的源端回执按演练阶段出现，和本地应用是否已处理某次回执是两回事。
`npm test` 核对可访问的上游响应和合成资料。

## 来源约定

`/drill/rounds` 是训练轮次、台账区域与领队。 `/drill/cards` 提供牌号的分配有效区间，结束不包含边界时刻。`/devices/index` 给出端侧开机批次，`/devices/A/memory` 及 `/devices/B/memory` 返回设备还未回收的缓冲，`through` 为本批声明末序号。同步时间经 `/devices/calibration` 给出的参考区间换算，每一条校时都给上下界，跨轮次边界时不能擅取中点。 `/devices/A/replay?boot=R9&from=2&to=2` 可补领缺片。
`POST /devices/{设备}/confirm` 接收 `boot`、`through`，表示上游可回收已连续接收的原件。演练服务器在下一阶段按已确认号隐藏原缓冲，历史动作需自行留存。`/drill/transfers` 返回随员领队批准的转接与医疗点回执，按转接号连接。

## 清点工具（本地应用）

`app/` 是消费上述来源的演练清点工具，不接真实告警。对指挥台而言，「人已经被转运、还没收齐签到、真的少了一人」三种情况在清点单上严格分开。

```sh
npm start                 # 终端一：启动本地合成来源
npm run demo              # 终端二：全流程演练（自带来源与临时数据目录，无需终端一）
npm run app -- --data ./drill-data sync --source http://127.0.0.1:4173
npm run app -- --data ./drill-data sheet --round R10
npm run app -- --data ./drill-data status
npm test
```

命令（`node app/cli.mjs [--data 目录] [--json] <命令>`）：

| 命令 | 说明 |
| --- | --- |
| `sync --source URL` | 同步一轮：拉取轮次/牌号/校时/缓冲/转接，补取缺片，确认连续号 |
| `sheet --round R10` | 当前清点单：已核实、已转运、转出未收、归属未定、只缺终端证据、仍待发现分列 |
| `status` | 值守台：每片区域由谁继续跟进、哪条离线段还等接收、转接停在哪一方 |
| `sign --round R10 --leader L1` | 领队签收阶段清单，保有当时的点位及资料 |
| `claim --round R10 --person X1 --leader L1` | 晚到扫描更正当前清点后，领队认领更正 |
| `seal --round R10 --leader L1` | 封清点单；存在未决项时拒绝并列出原因 |
| `trace --round R10 --person X9` | 溯源：牌号分配、源记录、转接链、签收历史 |
| `record --id 'A\|R9\|3'` | 定位单条源记录及其归属判定 |
| `stages --round R10` | 查看已签阶段单 |
| `reverify` | 从已保存源记录复核全部归属与已确认段 |
| `reroute --round R10 --person X1 --to-point E1 --by V5` | 志愿者申请改派通道（本地台账） |
| `issue-card --round R11 --person X7 --card 900 --by V3` | 给临时加入的演练人员补牌（本地台账） |

### 清点规则

- **归属判定**：校时记录给的是区间。整条扫描的时间区间唯一落入某一轮的牌号有效区间才计入该轮清点；跨轮次边界不擅取中点，暂挂候选，不计入。校时缺失时按牌号有效区间挂到每个可能轮次。
- **序号完整性**：由上传末尾声明（`through`/`end`）与实收序号共同判断。完成标记可能先于缺失中段到达；缺失段单独补取（`replay`）。同一扫描两次补交按 `设备|开机批次|序号` 去重，同序号内容不一致记异常并保留先到的源记录。
- **确认回收**：按已确认接收的连续序号向来源 `confirm`；确认前要求该段源记录已留存且归属已确定，归属未定的段不确认，保证重启后仍能从已保存源记录复核归属。
- **转接**：医疗点接收回执按转接号接回集合点批准的转接单；记录转出但未见接收时，跟进归属批准转接的领队，值守台标明停滞在接收方。
- **两点冲突**：同一轮次同一张卡在两个集合点被扫到，先看已接收的有效移交，无法确定时暂挂两个候选点位，不凭最新到达挑一个。
- **签收与更正**：阶段清单签收后保有当时点位及资料；晚到扫描确认此前去向时，当前清点更正并交该区域领队认领，原签收单及其查找安排保留。封单要求未决项（离线段、归属未定、转出未收、冲突、未认领更正）全部清零；确认缺失的人员以「仍待发现」如实入档。
- **轮次保护**：牌号按轮次有效区间归属，旧轮补录只影响旧轮清点，不改变当事人下一轮的所在队列。

### 数据留存

数据目录下 `state.json` 为台账状态（原子写），`source-log.jsonl` 为源记录日志（追加写，先于状态落盘）。重启时自动重放日志中未应用的条目；`reverify` 用日志从头复核归属与已确认段。本地台账（补牌、改派）不来自源记录，复核时单独列出。
